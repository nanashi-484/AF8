### 合成時序約束與初步結果（2026-05-05）

**工作站**：TSMC 40nm (sc9_cln40g_base_rvt)，Synopsys Design Compiler R-2020.09

**約束設計**：

| 參數 | 原始值 | 修正值 | 說明 |
|------|--------|--------|------|
| `CYCLE` | 10.0 ns | 10.0 ns | 100 MHz 目標時脈 |
| `INPUT_DLY` | 5.0 ns (50%) | **1.0 ns (10%)** | 外部 register clock-to-Q + wire delay |
| `OUTPUT_DLY` | 5.0 ns (50%) | **1.0 ns (10%)** | wire delay + 外部 register setup time |
| `clock_uncertainty` | 0.1 ns | 0.1 ns | 時脈抖動裕量 |

**修正原因**：FP8_MAC 為純組合邏輯（僅內部 accumulator 為 sequential），input/output delay 各設 50% 會佔滿整個時脈週期（5+5=10ns），組合邏輯完全沒有可用時間。實際組合邏輯延遲僅 ~5.26ns，10% 反映真實的 register-to-register 情境（clock-to-Q ≈ 0.3ns, setup ≈ 0.2ns, wire ≈ 0.5ns）。

**時序分析**（路徑：in_b[5] → out_result[*]）：

```
data arrival   = INPUT_DLY + 組合邏輯 = 1.0 + 5.26 = 6.26 ns
data required  = CYCLE - OUTPUT_DLY - uncertainty = 10.0 - 1.0 - 0.1 = 8.90 ns
slack          = 8.90 - 6.26 = +2.64 ns  ✓
```

**關鍵路徑**：Multiplier → 28-bit Adder（27 級 ADDF ripple-carry，~1.35ns）→ Normalizer（LZD + RNE，~2ns）

**面積結果**：

| 項目 | 數值 |
|------|------|
| Total cell area | 1847.5 µm² |
| Combinational cells | 1388 |
| Sequential cells | 37（acc_register: 1+8+28 bits） |
| 製程 | TSMC 40nm |

理論最高頻率（不計 I/O overhead）：1 / 5.26ns ≈ **190 MHz**。

### MAC
論文實驗對比的是「MAC 資料路徑」本身，也就是一個乘積-累加運算最核心的硬體區塊。它的簡化架構如下：
```
        A[7:0]       B[7:0]
          │             │
     ┌────▼────┐  ┌────▼────┐
     │ Decode  │  │ Decode  │  解出 Sign, Exp, Mant (含隱藏位元)
     └────┬────┘  └────┬────┘
          │    ┌───┘
     ┌────▼────▼────┐
     │  Multiplier  │  指數相加(+Bias補償), 尾數相乘(4×4)
     │  Array       │  得出乘積 Sign_prod, Exp_prod, Mant_prod (寬)
     └─────┬────────┘
           │
     ┌─────▼────────┐
     │  Align & Add │  乘積與累加器中的舊值對齊後相加
     │  (Accumulate)│  → 這裡也會處理 Subnormal
     └─────┬────────┘
           │
     ┌─────▼────────┐
     │ Normalize &  │  正規化、捨入(Norm./Round) → 最終 FP8 格式
     │ Round        │
     └─────┬────────┘
           │
         Result[7:0]
```
重點說明：

- 這個 MAC 運作在一個「**更高精度的內部累加器**」上（通常是 FP16 或 FP32），才能保證多次乘加不丟失精度。論文比較的正是這一段運算的組合邏輯與暫存器面積。

- 乘法器負責產生「乘積」這一筆新數據；加法器負責將乘積與歷史累加值相加。這兩者在硬體上合在一起就是一個 MAC 單元。

- 如果你要復現論文的表 III，你的頂層模塊邊界就畫在這裡：輸入兩個 FP8 運算元，輸出一個 FP8 格式的累加結果（或直接輸出內部高精度值給下一級）。面積、功耗分析只針對這個模塊內部的組合邏輯與正反器。

### AF8 設計決策

- **管線**：單週期（純組合邏輯 + Accumulator Register），與 FP8 一致
- **內部精度**：24-bit mantissa + 10-bit signed exp（配合 aligner 的 `{3'b0, man_acc}` 介面）
- **正規化**：MSB 對齊至 bit 23，左移公式 = `26 - msb_pos`
- **E_cand 公式**：`(acc_exp + 14) >>> 1`（下界慣例，mantissa ∈ [2, 7]）
- **AF8 輸出編碼**：Sign-Magnitude（正數直接、負數反相 magnitude）
- **NaN 編碼**：`8'h7C`（正 NaN，E=15, M=4）
- **捨入模式**：Round to Nearest Even (RNE)
- **iverilog 相容性**：避免 variable part-select（改用 shift-and-mask）、避免 function output port、避免 `**` 運算子

### AF8 修正歷程（2026-05-05）

| 問題 | 模組 | 修正 |
|------|------|------|
| 左移量缺少 3 bits（`23 - msb_pos` vs `26 - msb_pos`） | Normalizer | 左移公式修正為 `26 - msb_pos` |
| Variable part-select（`acc_mant[right_shift-3:0]`） | Normalizer | 改用 shift-and-mask |

### AMAX（不需實作）
AMAX 運算不應該放在乘法器/加法器的內部，它不是 MAC 運算的一部分，而是張量預處理單元。一個完整的帶 AMAX 的 FP8 加速器資料流如下圖：
```
  ┌───────────────┐
  │ FP16 Tensor   │  來自記憶體的原始 Activation
  └───────┬───────┘
          │
  ┌───────▼───────┐
  │  Block AMAX   │  1. 逐區塊尋找絕對值最大值 (amax)
  │  Calculation  │  2. 輸出 amax 值、反數 (1/amax) 或移位量
  └───────┬───────┘
          │
  ┌───────▼───────┐
  │  Scale &      │  所有元素除以 amax (乘法或移位)
  │  Quantize     │  並轉換成 FP8 格式
  └───────┬───────┘
          │
    FP8 Activations
          │
  ┌───────▼───────┐
  │   MAC Array   │  這裡才是你之前練習的乘法器＋加法器
  │  (FP8 × FP8)  │  內部完全不碰 amax
  └───────┬───────┘
          │
    乘積 (內部高精度)
          │
  ┌───────▼───────┐
  │ Rescale &     │  將 amax_A * amax_B 乘回，並量化回最終格式
  │ Output Quant  │
  └───────────────┘
```
- AMAX 計算單元
    一個小型的比較樹（多級比較器與絕對值電路），僅在資料流入 MAC 陣列之前運作一次。它不是每個乘法都要跑，而是每整個區塊共享一次。

- Scale & Quantize 單元
    包含一個乘法器（乘以 1/amax）和一個「高精度→FP8」的量化邏輯（考慮捨入）。

- Rescale 單元
    在 MAC 陣列之後，把 amax 係數乘回累加結果。這個乘法通常是一次性的（例如使用一個較寬的乘法器），因為 scale 的數量遠少於 MAC 運算次數。
